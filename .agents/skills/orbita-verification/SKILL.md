# Проверка Орбиты

Найти корень проекта и прочитать docs/STATUS.md и TESTING.md. Выбрать проверки под изменение, а не прогонять весь список для каждой правки.
Для логики проверить изменённое поведение и соседний критический сценарий. Для визуала проверить кадр и доступность взаимодействий. Для сборки запускать сам player, а не только редактор.
Фиксировать среду, команду или ручной сценарий, результат и оставшиеся ошибки. Не называть headless-тест визуальной проверкой.

Критический проход: движение → лифт вверх/вниз → терминал → принятие → повторное открытие → выход и возврат управления.
Сохранение между запусками пока отсутствует; не считать сброс принятого заказа регрессией до появления соответствующей задачи.
Публичную ссылку считать проверенной только после успешного развёртывания и проверки доступности актуальной игры. Push кода и настройки экспорта не доказывают публикацию.

Если Unity недоступна, выполнять доступные статические проверки и честно обозначать, что импорт/компиляция/Play Mode не проверены. Обновлять STATUS фактическим результатом, не менять критерии ради формального успеха.
